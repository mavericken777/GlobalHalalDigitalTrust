## 1. Website purpose

The website must be rebuilt from the ground up around the actual operating system of the project. It must not present Global Halal Supply Chain Limited (GHSCL), AHTE, PHC, JAKIM, laboratories, logistics providers or GCC destination actors as interchangeable roles.

The website has four jobs:

1. Explain the complete end-to-end Halal Digital Trust infrastructure accurately.
2. Convert China manufacturers/producers into qualified onboarding candidates.
3. Give authorities, laboratories, logistics operators, buyers/importers and partners a clear view of how they connect to the trust fabric.
4. Provide a public verification surface for authorised trust records, product/batch/shipment status and certification state.

The site must communicate one core proposition:

> **Complete traceability. Live Halal status. Immutable evidence. Human authority. From raw-material origin to GCC destination.**

## 2. Project operating model represented on the website

### 2.1 Institutional / operating roles

| Layer | Actor | Website description |
|---|---|---|
| Malaysian halal-industry institutional layer | Perak Halal Corporation (PHC) | Perak State Government halal-industry GLC operating locally and internationally |
| International JV / operating layer | Global Halal Supply Chain Limited, Hong Kong | International operating and digital-infrastructure vehicle |
| Intelligence layer | AHTE | Continuous standards, evidence, traceability, compliance and trust intelligence |
| Authority connectivity | JAKIM API integration | Direct authority-system connectivity and real-time/near-real-time authorised status exchange according to the implementation contract |
| Scientific evidence | Project-designated China government laboratory pathway | Origin/sample/testing evidence within authorised scope |
| China origin ecosystem | Manufacturers, producers, suppliers, laboratories, warehouses, logistics providers, ports | Production/origin operating environment |
| GCC destination ecosystem | Importers, authorities, customs, warehouses, retailers, buyers | Primary destination-market environment |
| AI | AHTE AI assistance | Continuous evidence-gap detection, anomaly detection, correlation and verification support |
| Human certification decision | PHC + JAKIM mufti/scholars / authorised human authority workflow | Formal certification approval/disapproval under the project operating model |

### 2.2 Non-negotiable website distinction

The public site must visually and verbally distinguish:

`GHSCL infrastructure ≠ AHTE intelligence ≠ laboratory evidence ≠ AI recommendation ≠ authority certification decision`

The system provides complete traceability and live Halal status/trust state. Formal certification approval/disapproval remains a human authority decision.

## 5. Homepage architecture

### Section 1 — Hero

**Eyebrow:** GLOBAL HALAL DIGITAL TRUST INFRASTRUCTURE

**Headline:**  
# From Origin to GCC. Every Material. Every Evidence. Every Handover. Verifiable.

**Subheadline:**  
Global Halal Supply Chain Limited operates an international digital-trust infrastructure connecting the Malaysian halal ecosystem, China-origin manufacturers, authorised laboratory evidence, real-time supply-chain monitoring and GCC destination markets through AHTE.

**Trust line:**  
**Complete traceability · Live Halal status · Immutable evidence · Human authority**

Primary CTA: **Onboard a Manufacturer**  
Secondary CTA: **Verify a Trust Record**

Hero visual: interactive China → Malaysia governance/assurance → GCC trust corridor with live evidence nodes.

### Section 2 — The complete chain

Title: **One Trust Chain. Source to Shelf.**

Interactive horizontal/vertical chain:

`Raw-material origin → Supplier → Sample → Laboratory → Manufacturing → Packaging → Warehouse → Logistics → Port / Export → International Transit → GCC Import → Distribution → Retail / Verification`

Each node should reveal:

- identity;
- actor;
- applicable requirement/control;
- evidence type;
- timestamp;
- integrity proof;
- current state;
- exceptions.

### Section 3 — Three truths

**Traceability**  
The system reconstructs the complete material, product, batch, shipment and custody genealogy.

**Halal status**  
AHTE continuously computes and displays the current evidentiary/operational Halal trust state and propagates formal certification status.

**Human authority**  
AI assists monitoring and verification. Formal certification approval/disapproval is a human authority decision through the PHC/JAKIM workflow.

### Section 4 — Institutional architecture

Four clearly separated cards:

- **PHC** — Malaysian state-government halal-industry GLC; local and international halal-industry role.
- **GHSCL Hong Kong** — international JV operating and digital-infrastructure vehicle.
- **AHTE** — continuous standards/evidence/trust intelligence.
- **PHC/JAKIM human authority workflow** — certification approval/disapproval and formal status.

Do not draw JAKIM or PHC as a commercial subsidiary of GHSCL.

### Section 5 — Manufacturer onboarding

Title: **From Candidate Factory to Continuously Monitored Halal Production**

12-step visual:

1. Enterprise application
2. KYB / due diligence
3. Facility and process qualification
4. Product/SKU/formula/BOM mapping
5. Material and supplier provenance
6. Complete applicable standards resolution
7. HCP/SCCP and evidence plan
8. Laboratory/sample plan
9. Smart-glass on-site audit
10. Findings/CAR/re-verification
11. PHC/JAKIM human authority decision
12. Continuous monitoring + China→GCC release

CTA: **Start Manufacturer Onboarding**

### Section 6 — Smart-glass audit

Title: **AI-Assisted Site Audit. Human Auditor in Control.**

Show wearable field flow:

`Authenticate auditor/device → load assigned audit → verify facility/scope → load requirements/HCPs → walk facility → scan object → capture image/video/document/sensor evidence → immutable local hash → AI gap/anomaly assist → auditor finding → CAR → re-verification → sign/sync`

Capabilities to display:

- QR/DataMatrix/OCR/NFC scanning;
- image/video evidence;
- device + auditor identity;
- requirement-guided inspection;
- voice notes / commands;
- offline-first evidence capture;
- signed/hash-protected media;
- AI anomaly and missing-evidence assistance;
- human finding and sign-off.

### Section 7 — Laboratory + raw-material origin

Title: **Trust Begins Before Manufacturing.**

Explain that monitoring starts at the raw-material source and sample chain, not only at finished goods.

Visual:

`Source / farm / supplier → raw-material lot → sample → seal → chain of custody → laboratory receipt → method execution → authenticated result → immutable hash → material release/hold → manufacturing input`

Key message:

> A laboratory result is scientific evidence. It is bound to origin, sample identity, chain of custody and the applicable authority/control context.

### Section 8 — Complete standards intelligence

Title: **One Standards Intelligence Layer Across the Complete Applicable Halal Framework**

Do not frame the system as an MS 2400 platform.

AHTE routes applicable requirements from:

- Malaysian halal standards corpus;
- JAKIM operative certification instruments;
- MPPHM / MHMS / applicable protocols and circulars;
- product/sector requirements;
- destination-market requirements;
- contractual buyer/importer requirements where applicable.

Visual canonical path:

`Authority → Standard / Instrument → Requirement → Applicability → Control → HCP/SCCP → Evidence → Audit → Finding → CAPA → Re-verification → Authority Gate → Trust State → Operational Release`

### Section 9 — Immutable evidence fabric

Title: **Every Material Evidence Object Can Be Proven Unchanged.**

Display evidence structure:

`Actor + Object + Event + Evidence + Timestamp + Device/System + Requirement + Hash + Signature/Authentication + Previous-event reference`

Public explanation:

- evidence is hash/integrity protected;
- original evidence is not silently overwritten;
- corrections create traceable supersession/history;
- chain-of-custody and audit history remain reviewable;
- role-based access controls what each stakeholder can see.

Do not claim that hashing or blockchain independently proves Halal status.

### Section 10 — Real-time monitoring

Title: **Certification Is Not the End of Monitoring. It Is a State in a Living Trust Graph.**

Live monitored event examples:

- supplier/material changes;
- certification expiry/status changes;
- lab evidence;
- manufacturing events;
- HCP/SCCP exceptions;
- cleaning/segregation controls;
- packaging and batch identity;
- warehouse receipt/dispatch;
- container and seal events;
- route/geofence deviation;
- environmental telemetry;
- custody transfers;
- GCC receiving;
- CAPA/re-verification;
- suspension/revocation/recall.

AI assist categories:

`Evidence gap · anomaly · contradiction · trust-graph fracture · predictive compliance · recall blast radius`

### Section 11 — JAKIM API / authority connectivity

Title: **Authority-Connected, Not Authority-Replacing.**

Explain the project operating model:

`AHTE ↔ Authority API Gateway ↔ JAKIM authority system`

Public wording should emphasize authorised status/evidence exchange, human decision control, traceable authority events and continuous status propagation.

Do not expose endpoint names, credentials, internal schemas or security-sensitive implementation details publicly.

`China manufacturer → laboratory / origin evidence → factory audit → certification decision → monitored warehouse/logistics → export/port → transit → GCC port/importer → destination warehouse → retail/consumer verification`

## 8. Design direction

The website should look like **critical digital infrastructure / institutional trust technology**, not a generic halal consultancy and not a cryptocurrency site.

### 8.2 Visual language

- dark institutional base;
- precise emerald/green trust accents;

- high-contrast data visualisation;

### 8.3 Interaction language

- live trust graph animations;
- end-to-end corridor map;
- scroll-linked chain stages;
- expandable evidence cards;
- smart-glass audit simulation;
- trust-record lookup;
- role-based journey selector;

### 8.4 Accessibility

- WCAG-conscious colour contrast;
- keyboard navigation;
- semantic headings/landmarks;
- reduced-motion alternative;
- screen-reader labels;

## 10. Technical web architecture

Recommended implementation:

- Next.js / React / TypeScript;
- server-rendered/static public pages;
- authenticated portal surfaces separated from public marketing routes;
- governed content objects for standards/partners/claims;
- API gateway for verification/status queries;
- role-based access control;
- audit logging for authenticated trust views;
- multilingual routing;
- structured SEO metadata;
- OpenGraph/social assets;
- privacy/security headers;
- analytics with minimal data collection;
- separate production / staging environments.

Suggested repository path: `platform/web/`.

### 10.1 Content governance

Public claims should be sourced from governed repository content rather than duplicated manually across pages.

Recommended data sources:

- `partner-registry.json` for ecosystem roles/status;
- standards registry / verified stack for standards list/version;
- corridor registry for China→GCC route definitions;
- trust-packet schemas for verification views;
- authority-status integration for certification state;
- website-specific public-copy registry for controlled claims.

### 10.2 Security

Do not expose:

- JAKIM API endpoint details;
- credentials or tokens;
- internal authority workflow secrets;
- laboratory private data;
- manufacturer trade secrets/formulas;
- raw cross-border data not approved for disclosure;
- internal risk scores where disclosure is not authorised.

Use selective disclosure and role-based views.
