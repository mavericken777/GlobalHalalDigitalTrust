# Regulatory and Laboratory Interoperability Framework

## Core governance rule

The ecosystem connects sovereign authorities; it does not replace them. Each regulator retains legal authority over its jurisdiction. The platform provides evidence, workflow, interoperability and auditability.

## JAKIM / Malaysia and China laboratory concept

The proposed workflow discussed for the China laboratory is:

`raw-material origin → laboratory submission → testing against applicable requirements/SOP → laboratory report → manufacturer + authorized regulatory/evidence channels → certification decision → production/supply chain`

The Chinese laboratory remains a Chinese institution under its applicable Chinese governance. JAKIM remains Malaysia's competent halal authority. Any formal recognition, authorization, endorsement, use of marks, data transfer or fee arrangement must be documented by the competent authorities.

## Evidence package

A laboratory event can include:
- sample identity;
- chain of custody;
- test method/version;
- laboratory identity and authorization;
- instrument/calibration evidence where applicable;
- test result;
- analyst/approver identity;
- timestamp;
- digital signature/attestation;
- report hash;
- corrective-action history.

## Interoperability model

The ecosystem should establish a minimum evidence set and common schemas while allowing each jurisdiction to retain local forms, procedures and decision rules.

## Regulatory API gateway

Potential functions:
- submission intake;
- evidence retrieval;
- status exchange;
- verification request;
- certificate/credential validation;
- laboratory result exchange;
- alerts and recalls;
- audit requests.

## Government integration principle

Legacy systems should be connected through adapters rather than replaced. New systems can consume the same canonical APIs. This makes the ecosystem an interoperability layer rather than a forced national-system replacement programme.

## Government marks and commercial arrangements

No government logo, endorsement, accreditation claim, royalty, licensing fee or recognition status should be represented as final until a written authorization exists. The commercial proposition should focus on ecosystem participation and mutual value, not implied ownership of governmental authority.

## Cross-border data

Cross-border exchange must use purpose limitation, data minimization, explicit policy, authentication, authorization, encryption and jurisdiction-specific legal controls. Where a fact can be verified without transferring the underlying sensitive record, prefer a verifiable credential or cryptographic proof.
