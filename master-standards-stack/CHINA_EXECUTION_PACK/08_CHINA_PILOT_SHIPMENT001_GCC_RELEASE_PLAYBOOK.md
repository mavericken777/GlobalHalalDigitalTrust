# 08 — CHINA PILOT → SHIPMENT 001 → GCC RELEASE OPERATING PLAYBOOK

## 0. Outcome

Establish a repeatable China-origin halal trade corridor in which qualified manufacturers can be activated, controlled products can be produced with auditable provenance, and Shipment 001 can move directly from China to a GCC destination through a digitally traceable physical chain.

## Phase 0 — Programme mobilisation

**Inputs:** mandate, target corridor, participating departments, initial product list, target GCC market.

**Actions:** create programme case; appoint accountable HODs; establish RACI; establish rule registry; establish security/data governance; create China/Malaysia/GCC jurisdiction profiles.

**Gate G0:** governance board, escalation routes, data-zone architecture and Shipment 001 scope approved.

## Phase 1 — China manufacturer activation

**Actions:** verify legal entity and facility identity; collect product/SKU list; map suppliers/materials; establish responsible QA/compliance roles; connect factory gateway; perform digital and physical baseline assessment.

**Gate G1:** facility active, roles authorised, system identity established, product scope classified.

## Phase 2 — Factory qualification

**Actions:** execute AHTE audit; map applicable MS controls; establish HCPs; verify zoning/segregation; review sanitation/handling; inspect source materials; verify traceability; test data interfaces; close mandatory actions.

**Gate G2:** qualified factory profile, active control plan, evidence graph operational.

## Phase 3 — Product/material assurance

**Actions:** register materials and supplier evidence; classify animal/plant/mineral/synthetic source; evaluate transformation routes; review packaging and labelling; connect relevant analytical evidence; bind formula/process versions.

**Gate G3:** all mandatory material and process controls have evidence and authorised disposition.

## Phase 4 — Production of Shipment 001

**Actions:** create production order; freeze formula/process version; open HCP monitoring; receive/verify materials; capture production events; collect samples; record lab results; create batch/lot identity; QA disposition.

**Gate G4:** every shipment candidate is traceable to a released batch/lot with complete event sequence.

## Phase 5 — Shipment construction

**Actions:** select released lots; create pallet objects; bind package/serialization where applicable; inspect pallet condition; create container object; verify loading area; load pallet set; apply seal; photograph/record seal; issue shipment dossier.

**Gate G5:** shipment graph complete and physically reconciled.

## Phase 6 — China export

**Actions:** carrier/vehicle verification; custody transfer; export documentation; customs declarations; port intake; inspection as required; export release; departure milestone.

**Gate G6:** export state confirmed and seal/custody chain intact.

## Phase 7 — Transit control tower

Monitor:

`ETA -> location -> custody -> seal -> temperature/condition where applicable -> exception -> route change -> document event`.

Every exception creates a traceable case and determines whether the shipment continues, pauses or requires authority referral.

## Phase 8 — GCC pre-arrival

**Actions:** transmit authorised pre-arrival data; validate importer/consignee; prepare destination document pack; run destination rule-precedence check; pre-authorise port officer views.

**Gate G7:** destination admission package prepared.

## Phase 9 — GCC border

**Actions:** container/seal scan; identity reconciliation; document checks; inspection/sample where required; customs procedure; competent-authority actions; release/hold decision.

**Gate G8:** border release event recorded.

## Phase 10 — Destination warehouse

**Actions:** custody transfer; seal inspection; receiving inspection; inventory status assignment; quarantine where needed; release into warehouse; preserve lot/container genealogy.

**Gate G9:** warehouse release.

## Phase 11 — GCC retail release

**Actions:** retail receiving; display/storage controls; product identity and label verification; trust-view availability; complaint channel; recall readiness.

**Gate G10:** retail release.

## Shipment 001 daily control tower

Morning: shipment state, exceptions, ETA, documents, custody, seal.  
Midday: manufacturing/batch status, lab queue, evidence completeness.  
Evening: risk changes, authority actions, next-milestone confirmation.

## Critical stop conditions

Stop or hold on: identity mismatch; unapproved material substitution; failed/contradictory required evidence; uncontrolled process change; compromised seal; unexplained custody break; destination document deficiency; authority hold; confirmed recall condition.

## Recall drill

Run one tabletop exercise before Shipment 001 departure:

`trigger -> identify affected batch -> trace to pallets -> container -> custody -> destination -> warehouse -> retail -> customer/consumer notification -> containment -> reconciliation -> closure`.

## KPI set

- 100% batch-to-container genealogy.
- 100% custody events signed.
- 100% seal events linked to physical and digital identity.
- 100% mandatory HCP evidence captured.
- 0 unexplained custody gaps.
- 0 duplicate event IDs.
- < defined target for exception acknowledgement.
- < defined target for synchronisation latency.
- recall blast-radius determination within the agreed operational SLA.

## Exit to scale

Scale only after a formal post-Shipment-001 review covering authority interfaces, factory adoption, data sovereignty, cyber controls, logistics reliability, border operations, GCC destination acceptance, evidence quality, recall performance and commercial economics.
