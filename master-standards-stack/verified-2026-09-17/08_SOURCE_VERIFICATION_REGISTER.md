### Manufacturer-source rule

Manufacturer sites may support product capability, stated certificates, export-market claims and contact/discovery information. Final qualification requires independent E2-E5 evidence: legal records, signed certificates, issuer/recognition verification, specifications/formulae, regulatory registrations, commercial documents and transaction-native evidence.

## 7. Source provenance fields

Every cited source in AHTE should carry:

`SourceID; Issuer; SourceType; Title; URL/RepositoryPath; Jurisdiction; PublicationDate; AccessedAt; Edition/Version; EffectiveDate; Supersedes; Status; Hash where controlled; Copyright/AccessClass; ClaimsSupported; ClaimsNotSupported; Reviewer; LastVerified; NextReviewTrigger`.

## 8. Verification cadence

- authority recognition lists: check before supplier qualification and again before shipment release;
- halal/product certificates: check at onboarding, before production release and before shipment release;
- standards/procedure versions: check at project phase gate and before audit/certification use;
- destination import/label requirements: check for every SKU/country before artwork lock and shipment;
- manufacturer commercial claims: refresh before outreach/contract;
- retailer/category signals: refresh when preparing actual sales/buyer case; never preserve as timeless demand evidence.

## 9. Source conflict rule

If repository interpretation conflicts with a later competent-authority/current normative source:

`STOP AUTOMATIC RELEASE -> OPEN SOURCE-CONFLICT -> FREEZE AFFECTED RULE -> IDENTIFY TRANSACTIONS/CONTROLS -> AUTHORITATIVE REVIEW -> UPDATE VERSIONED RULE -> IMPACT ASSESSMENT -> RE-VERIFY AFFECTED OBJECTS -> RELEASE/REJECT`.

The authoritative current source takes precedence within its mandate; historical repository text is retained only as provenance.
